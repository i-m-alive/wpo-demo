wpo-reference: test plan

20 Nov 2026 · A step-by-step check that what the team email asked for is met, done by hand. Part 1 checks the WPO project on its own (email tasks 1 and 2). Part 2 checks it in the NaviStorm console (email task 3). Every step says what to do, and what you should see. Background: audit, DEMO.md.

Button something to clicktext something to type✓ what you should see

What "done" means: the email's expectations, numbered. Each step below proves one or more of these. The record table at the end ticks them off.

  1. E1 Six stand-in systems answer exactly as the email's table.
  2. E2 Each stand-in sits behind an MCP server; the write tools are marked destructiveHint: true.
  3. E3 Agents never call a stand-in directly, only through MCP.
  4. E4 A LangGraph supervisor runs nodes 1–4 in order; compliance "pass" goes to writeback, "fail" back to the optimizer.
  5. E5 manager_copilot is a separate graph with its own entry point and business hours.
  6. E6 Retry settings exactly as the email; the unbounded retry is marked so nobody fixes it.
  7. E7 NaviStorm draws 1 orchestrator, 5 agents, 11 MCP tools, 6 systems, 18 edges, with nothing configured by hand.
  8. E8 Each node is classified from traces and MCP manifests.
  9. E9 Each node and edge records which source classified it.
  10. E10 No benchmarking, load generation or performance measurement.

S2 · NaviStorm settings (backend/.env, each on a line of its own, no comment after the value)

LineWhy
CHAOS_ENABLED=0Hides the M0–M4 screens (Journeys, Fault library, Experiments …): the console shows only onboarding, topology and the sandbox, like main. Use 1 if you also want to show those

Your database is already at the version this branch needs (migration 0008); nothing to migrate. For a clean demo you can point DATABASE_URL at a new file instead (e.g. sqlite:///./navistorm-demo.db): NaviStorm creates it on start.

S3 · Start everything

  1. Docker Desktop running: docker info prints server details.
  2. NaviStorm API: cd ~/Desktop/NaviStorm/backend && .venv/bin/uvicorn navistorm.main:app --port 8765 ✓ "Application startup complete"
  3. NaviStorm console: cd ~/Desktop/NaviStorm/frontend && npm run dev, open the address it prints, press Cmd+Shift+R, sign in (developer sign-in: tick every role).
  4. ✓ With CHAOS_ENABLED=0: the left menu has no "Resilience" group and no "Journeys", but has "Runtime plan" and "Sandbox runs".
